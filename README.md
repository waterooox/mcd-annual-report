# 麦麦年度报告 · MCD Annual Report

> 不是给你贴一个标签，而是把你这一整年在麦当劳的每一单，讲成一段**可以翻页读完、每句话都指得回订单号**的年度故事。

基于麦当劳中国官方 MCP 开发 · 使用腾讯 WorkBuddy 完成 · 仅读取账户数据，花钱动作一律需你确认

仓库地址：<https://github.com/waterooox/mcd-annual-report>

---

## 这是什么

市面上大多数"麦当劳年度报告"都在做同一件事：读几个只读接口 → 用一套权重给你打一个标签（你是"薯条原教旨主义者"）→ 渲染成一张图。

**麦麦年度报告做的不一样。** 它有三点硬差异：

| # | 差异 | 说明 |
|---|---|---|
| **1** | **全屏叙事，一屏一个结论** | 不做一张长表格，而是**分屏滚动**：开场 → 花了多少 → 最常去哪 → 反复点什么 → 什么时段 → 人格揭晓 → 还剩什么 → 诚实收尾。点任意处像翻书一样翻页。 |
| **2** | **可回溯（落在数据层）** | 屏面上只说结论，但每一屏都携带 `evidence` —— 来源**订单号 / 券 ID** 写进导出的 JSON。页面不挂公式面板是为了沉浸感，不是为了藏证据。 |
| **3** | **麦麦人格可证伪** | 用"吃得最多的东西"给你封个有梗的号（薯条钢琴家 / 旋麦 / 可劲儿乐呵…），但**文案里每个数字都来自真实订单，判定条件全部公开**。数据撑不起就诚实回落兜底人格。你可以核验，也可以反驳。 |

## 为什么它"真实使用"了 MCP

本项目不是把 MCP 当数据源草草调用两下，而是按**业务链路**串联只读工具：

```
只读采集                          本地计算                     渲染
──────────────────────────────────────────────────────────────────────────
now-time-info     ┐
order-list        ├──→  ledger_engine.py  ──→  render_story.py
query-order       │     （人格判定 + 叙事剧本）    （分屏 HTML + 分享卡）
query-my-coupons  │
query-my-account  ┘
```

**边界同样明确**：麦当劳 MCP 还提供 `create-order` / `calculate-price` 等写操作，
本项目**一律不调用** —— 一份回顾性的年报只需要读历史，没有资格替用户花钱。

详见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

## 一种形态：叙事版

只做一个版本 —— 把力气全部投在**阅读体验**上：

| | 🎬 叙事版 |
|---|---|
| 文件 | `annual_report.story.html` |
| 形态 | **全屏分屏滚动**，一屏一个结论，点击 / 滚轮 / 键盘翻页 |
| 适合 | 自己看完、截图分享、发给朋友 |
| 回溯 | 人格屏「↺ 人格是怎么判的」展开候选清单；其余数字见导出的 JSON `evidence` |
| 数据缺口 | 收尾屏声明 |

早期还有一个"表格版"（报告版）承担逐条核对，现已**整体移除** ——
同一份数据出两份产物，对使用者是选择负担，对维护者是双倍成本。
逐条核对的需求改由**导出的 JSON** 满足：它保留了每一屏的 `evidence`
（来源订单号 / 券 ID），要审计直接读它，不必在页面里翻找。

## 叙事版的设计取舍

网易云年报的风格是"大字 + 抒情"，但那种做法有个隐患：**页面没地方放证据，数字变得不可验证**。

本项目的处理是——**外壳学它，内核守住**：

- ✅ 全屏分屏、点击任意处像翻书一样 3D 翻页（滚轮/键盘平滑滚动、渐入动画、进度条）
- ✅ 大字报式视觉冲击
- ✅ 文案**全部由真实数据生成**，不写无中生有的抒情句
- ✅ 小样本（订单 < 3）时主动声明"结论基于极小样本"
- ✅ 收尾屏明确声明"数据未提供的指标不展示、不估算"

**屏面不放证据，但数据里有证据。** 这是刻意的取舍：

- 屏面只说结论，不挂公式、不放「依据」展开面板 —— 保持"年度回顾"的沉浸感；
- 唯一的例外是人格屏的「↺ 人格是怎么判的」候选清单，因为它本身就是
  "人格可以证伪"这一卖点的证据；
- 其余数字的来源全部落在导出的 `annual_report.story.*.json` 里
  （每屏一个 `evidence` 字段，列出构成该结论的订单号 / 券 ID）。

这样处理，比"每屏底部都挂一条算法说明"更符合年报的阅读预期：
刷年报的人不想被公式打断，想核对的人也不该在分屏脚本里翻找。

## 视觉：麦当劳品牌设计语言

叙事版走的是**麦当劳品牌设计语言**，而不是通用的"深色渐变科技风"。三层构造全部由代码生成：

**① 符号层 —— 金拱门（Golden Arches）**

金拱门是整份年报的**核心视觉符号**，以"品牌签名"的规格出现在开场屏与结尾屏，
其余屏右上角以 6% 透明度作为水印。它的画法是：

```
两段二次贝塞尔圆弧  +  stroke-linecap:butt（垂直切边）  +  底部错位半格
→ 中轴处自然形成 M 字中缝
```

这个构造与麦当劳商标在**数学上同源**（双弧 + 垂直切边），但完全由本项目的
Python 代码绘制成 SVG，**不包含任何官方图片文件**，从根上规避素材版权问题。
官方配色 `红 #DA291C / 黄 #FFC72C` 作为 CSS 变量集中管理。

**② 色彩层**

暖白底 `#FFFBF5`（不是纯白），品牌红压顶导航条，开场屏用暖黄光晕收束视线，
结尾屏反转为深褐底 + 金色拱门 —— 形成"进场亮、收场沉"的阅读节奏。

**③ 排版层**

粗壮字重 800、负字距、超大数字、胶囊标签、黄色下划线强调条 ——
这些是麦当劳广告物料里的常见语汇，比通用科技风更贴合品牌调性。

背景纹理（薯条竖条 / 汉堡横向层次 / 网点）同样是纯 CSS 几何图形，
不使用任何官方摄影素材。

> **为什么不用真实商品图？** 接口返回的商品图 URL 带时效签名会过期，
> 一旦失效页面就是一片破图，反而拉低观感。用纯矢量符号既稳定又无版权风险。
> 若后续接入稳定的图片源，渲染器已预留 `onerror` 降级位，可平滑切换。

## 快速开始

### 0. 获取代码

```bash
git clone https://github.com/waterooox/mcd-annual-report.git
cd mcd-annual-report
```

**零第三方依赖**，只要有 Python 3.10+ 即可，无需 `pip install`。

### 1. 只想看看效果（零配置，30 秒）

无需 MCP Token，仓库自带演示数据：

```bash
cd scripts
python render_story.py     # 生成叙事版
# 打开 ../annual_report.story.demo.html
```

会生成完整的 2026 年度年报（基于 `mock/sample_year.json` 的演示数据），
页面上会有醒目的"演示数据"提示，不会与真实数据混淆。

### 2. 接入你的真实账户

**前置**：先申请麦当劳 MCP Token —— 见 [麦当劳 MCP Server 使用指南](https://github.com/M-China/mcd-mcp-server)。

在 WorkBuddy 中配置连接器（左侧边栏【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置MCP】），
填入 [`mcp-config.example.json`](mcp-config.example.json) 的内容，**把 `YOUR_MCP_TOKEN` 换成你的真实 Token**。

启用后，在对话框里说：

> 帮我生成 2026 年麦麦年度报告

WorkBuddy 会依次调用只读工具拉取数据、调用本仓库的 `ledger_engine.py` 计算、
再调用 `render_story.py` 渲染出 HTML 年报。

**开场屏署名**：MCP 接口**不返回用户昵称**，因此署名采用三级兜底：

1. 首次打开年报时，页面会弹出一层署名输入框（存 `localStorage`，只在本机保存）；
2. 跳过不填时，自动回落到**会员 ID 尾号**生成的署名（如「麦友 3118」，仅用末 4 位）；
3. 若在 `data/user.json` 的 `owner_name` 里预置了名字，则作为默认值。

页面上的会员 ID 一律只显示**末 4 位**，完整账号不会写入任何产物。

### 3. 直接读结构化结果

除 HTML 外，同时导出 `annual_report.story.demo.json`：它是渲染前的完整分屏剧本，
每一屏都带 `evidence`（构成该结论的来源订单号 / 券 ID），涉及计算的屏还带
`formula`（该结论怎么算的），便于二次开发或审计核对。

## 使用示例

**示例 1：看总账**

> 我今年在麦当劳花了多少钱？

输出：开场屏先给出**订单数**，第二屏给出**实付总额**与平均每单金额，
末尾给出「最常去的门店」「反复点的前三样」「最集中的时段」。

**示例 2：看资产**

> 我手上还有多少券和积分？

输出：资产屏给出**可用券张数**与**积分可用 / 累计获得**。
真实模式下，接口不返回券面额时会如实标注为「未提供」，不做估算。

**示例 3：看我是什么风格**

> 我是个什么样的麦当劳用户？

输出：悬念预告屏 → 人格屏。给出**具体封号 + 触发条件 + 实测数量**，
点开「↺ 人格是怎么判的」能看到所有命中人格的候选清单与各自数量，
数据撑不起具体人格时回落为「麦门永存」。

**示例 4：只想看数字，不想翻页**

> 把这份年报的原始数据给我。

输出：`annual_report.story.*.json` —— 完整分屏剧本，每屏带 `evidence`
（来源订单号 / 券 ID），涉及计算的屏还带 `formula`。
不改任何引擎代码即可二次开发。

## 麦麦人格：把"你吃得最多的东西"变成有梗的封号

叙事版的第 7 屏（人格屏，前有悬念预告页）是 **「你的麦麦人格是」** —— 这是整份年报最先被人截图转发的一屏。

它的逻辑很直接：**看你本年度累计吃得最多的是哪一类东西，就封你对应的称号。**

| 人格 | 触发条件 | 封号示例 |
|---|---|---|
| 🍟 **薯条钢琴家** | 薯条类累计件数最多 | 「8 盒一场八重奏、4 盒一场四重奏、2 盒一场双重奏……在薯门的世界里，你是名副其实的**救薯**。」 |
| 🎁 **极品小学生** | 随心配 / 1+1 最多 | 「1+1 之王，非你莫薯。」 |
| 🍦 **旋麦** | 麦旋风最多 | 「杯子转起来的时候，据说能看见『黑旋风』。」 |
| 🌽 **麦粒肿** | 玉米杯最多 | 「你无疑是台**玉米粉碎机**。」 |
| 🥤 **可劲儿乐呵** | 可乐最多 | 「气泡管够，快乐管饱 —— 看来你是一个非常快乐的人。」 |
| ☕ **咖麦隆** | 麦咖啡系列最多 | 「杯杯不落，场场首发 —— 咖啡界的全能前锋。」 |
| 🌶️ **麦辣战神** | 麦辣鸡腿堡系列最多 | 「别人的微辣是微辣，你的微辣是『再来一个』。」 |
| 🍔 **巨无霸原教旨** | 巨无霸最多 | 「经典之所以是经典，是因为你没换过。」 |
| 🧀 **吉士行乐** | 吉士汉堡系列最多 | 「融化的芝士从来不缺席你的一餐 —— 及时行乐，趁热吃堡。」 |
| 🍔 **堡你周全** | **所有汉堡之和**最多（仅作副人格，`sub_only`） | 「有面包、有肉、有酱，才叫一顿饭 —— 别的都是配菜。」 |
| 🌅 **清醒贩麦者** | 早餐时段单数最多 | 「清醒得早，麦得也早 —— 一天从一手交钱一手交汉堡开始。」 |
| 🌙 **国宝** | 夜宵时段单数最多 | 「熬最深的夜，点最香的餐 —— 黑眼圈就是你国宝级的勋章。」 |
| 🍰 **甜品特派员** | 甜品品类最多 | 「先吃甜的还是先吃咸的，你从来不纠结 —— 先吃甜的。」 |
| 🏛️ **麦门永存** | *（兜底）* | 「什么都点一点，这本身就是一种信仰。」 |

### 🥚 隐藏人格（条件命中才揭晓）

| 人格 | 触发条件 | 封号 |
|---|---|---|
| 🍗❄️ **冰矛鸡爪流** | **同一笔订单**里同时出现「鸡翅」和「冰激凌」，全年 ≥3 单 | 「先叠『冰矛』，再上『鸡爪流』连招 —— 峡谷里最会吃的那个召唤师。」 |

隐藏人格与普通人格有四处不同：

1. **不参与公开排名** —— 它不出现在「人格是怎么判的」候选清单里，
   否则一眼就能看出触发条件，就不叫隐藏了。
2. **一旦命中就顶替主人格** —— 彩蛋优先级最高，原主人格降为副人格（仍可回溯）。
3. **专属暗色皮肤** —— 深蓝底 + 青蓝辉光 + 「★ 隐藏人格解锁 ★」呼吸横幅，
   与其余屏的暖白/品牌红形成强烈反差，滚动到这一屏会有"突然换台"的冲击感。
4. **计的是订单数**，不是商品件数 —— 因为考的是"同一单里两样都点"这个**组合行为**。

### 五条硬规则（保证"有梗"不等于"瞎编"）

**① 文案里的每个数字都来自真实订单。**
「40 盒薯条 → 5 场八重奏」不是写死的文案，是引擎按
8 盒=八重奏、4 盒=四重奏、2 盒=双重奏 的贪心拆分现场算出来的。你数不出来，就说明我们算错了。

**② 门槛兜底，不硬塞标签。**
每个人格都有 `min_n` 门槛（薯条 8 盒、可乐 6 杯、早餐 4 单…）。
数据撑不起具体人格时，回落为「麦门永存」—— 而不是硬塞一个不符的封号。

**③ 同源去重 + 主人格排序。**
- 已被单品型人格认领的商品，不再计入宽泛的品类型人格
  （如「奥利奥麦旋风」算进「旋麦」，就不再重复算进「甜品特派员」）
- 累计数量最高的为**主人格**（大标题），其余至多 2 个为**副人格**（胶囊）
- 数量并列时，名字更具体的人格优先

**④ 全集型例外：`universal=True` + 仅副人格（`sub_only=True`）。**
「堡你周全」统计的是**所有汉堡之和**，它**主动参与**同源去重后的重复计数 ——
已被「麦辣战神」「巨无霸原教旨」认领的汉堡，它照样算进来，
这样它才能和单品汉堡人格在同一量纲上比大小。
但它**只做副人格，永不当主人格**（`sub_only=True`，用户要求）——
否则它会以"汉堡总和"这个天然占优的宽泛数值长期压制更具体的封号：
- 数值最高时也**只出现在副人格位**，主人格顺延给次高的单品人格
  （如 麦辣 16 + 巨无霸 12 = 28 → 主人格给 18 杯的「咖麦隆」，
  副人格展示「堡你周全 · 28 个」）
- 它在候选清单里被**排在最后**（不抢主人格顺位），仍可回溯
- 只有汉堡可统计时同理：12 个巨无霸 → 主人格「巨无霸原教旨」，副人格「堡你周全」

**⑤ 隐藏人格（`hidden=True`）单独判定，不混入候选清单。**
「冰矛鸡爪流」用 `match_pair` 声明两组关键词，要求**同一笔订单内同时命中**，
计的是订单数。它不参与公开排名，命中即顶替主人格。
详见下方「🥚 隐藏人格」小节。

### 展开就能看到判定过程

点开卡片里的「↺ 人格是怎么判的」，会列出**所有命中的人格**，
每条都带触发条件与实测数量 —— 这是叙事版里**唯一保留**的可回溯入口，
因为它本身就是"人格可以证伪"这个卖点的证据：

```
薯条钢琴家    商品名包含：薯条                  11 盒
咖麦隆        商品名包含：麦咖啡/拿铁/美式/…     18 杯
...
本年度商品明细：麦咖啡拿铁×18、麦辣鸡腿堡×16、麦旋风×14…
```

### 保存分享图

人格屏底部有「保存我的麦麦人格图片」按钮，点击后用 **Canvas 现场绘制**一张分享卡
（零依赖，不使用任何官方图片素材；金拱门由与网页**同一份路径常量**绘出，
并有一条断言 `check_arch_consistency()` 守着两边不跑偏）。

分享卡的版式与网页人格卡**逐块对齐**：kicker + 卡片红→黄渐变色带 + 人格名与累计数同行 +
逐条正文面板（左侧高亮竖线依次变淡）+ 档案说明框 + 卡外金拱门与版权行。

图片**只包含卡片内容**——返回按钮、「真实数据」徽标、保存按钮这类**界面控件不会画进图里**，
避免分享出去的图带着产品 UI 残留。

> 移动端浏览器会拦截 `a.download`，因此策略改为「弹出预览浮层 + 长按保存」，
> 桌面端与手机端都能拿到图。

另外附带一份 [`persona_preview.html`](persona_preview.html)：把**全部 15 个人格**（含隐藏人格）
的人格屏一次性并列展示，方便评委与路人不用真的攒够数据就能看全所有封号。

这是本项目与"贴个标签就完事"的同类项目的分水岭：
**封号可以好玩，但判定过程必须公开。**

### 为什么没有"四维度行为画像"屏

早期版本在人格屏之后还叠了一屏「支撑这个人格的行为佐证」，
把套餐依赖度 / 时段集中度 / 口味多样性 / 客单价位四个维度铺开。

它已**整体移除**，原因有两条：

1. **节奏**：人格屏本身就是一份完整的证书卡，再叠一屏会让"年度回顾"的节奏拖沓。
2. **可证伪性已被人格屏满足**：人格屏的「↺ 人格是怎么判的」已经公开了
   每个人格的触发条件与实测数量，本身就可以核验、可以反驳，不需要第二套判定体系。

> 这是删除，不是藏。项目的判定原则没变：
> **只描述可观测的点餐行为，不做黑箱权重打分；规则与阈值公开，可核验、可反驳。**

## 设计原则

1. **不编造**。账户没订单就诚实产出"空白年报"，绝不用假数据凑版面。
2. **可复算**。一切数字只用加减乘除，不引入不可解释的权重。
3. **只读优先**。默认全程只读，仅调用只读工具；本项目不发起任何下单动作。
4. **演示与真实分明**。mock 数据在页面上有强提示，不会误导。
5. **可证伪**。屏面说结论，JSON 里给依据；拿不到的指标如实声明缺口。

## 目标用户

- 想知道"我在麦当劳一年花了多少、怎么花的"的**普通用户**
- 喜欢年度总结、愿意把结果截图分享的**社交型用户**
- 对"系统给我贴的标签"不服气、想看判定依据的**较真型用户**
